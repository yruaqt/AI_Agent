# 榄园知行——6 分钟智能体开发大赛讲解脚本

适用场景：项目讲解视频、答辩录屏、现场演示。

建议总时长：5 分 40 秒至 6 分 10 秒。语速保持自然，避免逐字飞快朗读；屏幕演示时可停顿 1～2 秒让评委看清关键结果。

---

## 一、录制思路

视频的核心不是展示页面数量，而是让评委在 6 分钟内看懂一个完整的智能体闭环：**它服务谁、为什么需要 Agent、Agent 依据什么做判断、会调用什么工具、结果如何落到真实业务和教学记录中。**

建议录屏顺序如下：

1. 片头与项目定位：系统名称、应用场景、项目全景。
2. 痛点和目标：传统资料分散、建议缺少具体果园上下文。
3. 智能体架构：果园上下文 + RAG + 工具调用 + 流式对话 + 任务闭环。
4. 核心演示：登录、果园档案、一次带天气与用量计算的对话、来源引用和工具状态。
5. 业务闭环：农事任务、实训记录、权限和可追溯性。
6. 技术亮点、价值与展望。

录制时优先展示真实页面与真实结果；模型或天气 API 不稳定时，提前准备演示账号、预置果园资料和录屏备份。不要把演示天气数据说成实时天气，页面或话术中应明确数据来源和更新时间。

---

## 二、录制前准备清单

- 准备管理员和学生两个账号；浏览器提前登录学生账号。
- 预置“学校东区橄榄实训果园”，确保面积、株数、品种、滴灌方式、当前物候期等字段完整。
- 知识库至少有可引用的橄榄水肥、病虫害或采收资料。
- 预先打开首页、智能问答、今日农事、实训记录四个页面标签。
- 准备一个可稳定展示的提问：

  `未来两天有大雨，幼果膨大期的橄榄园是否需要灌溉和施肥？同时计算 300 株、每株 20 升的灌溉量。`

- 如需展示药剂计算，可使用：

  `配制 200 升药液，按 1000 倍稀释，原药理论用量是多少？`

- 放大浏览器到 110%～125%，隐藏无关标签、通知和密钥信息。
- 录屏分辨率建议 1920×1080；麦克风保持距离一致，片头和切页预留短暂停顿。

## 三、6 分钟分镜与逐段话术

### 0:00～0:30｜片头：一句话说明项目

**建议画面**：项目首页或标题页，随后切到系统总览页面。

**讲解话术**：

> 各位评委老师好，我们的参赛项目是“榄园知行——面向校园橄榄实训果园的智能管理与农事决策系统”。它不是一个只会聊天的农业问答机器人，而是一个面向真实果园实训场景的智能体。系统把果园档案、物候期、专业知识库、天气信息和农业计算工具组织起来，帮助学生和教师完成从咨询、决策到任务执行与记录沉淀的闭环。

### 0:30～1:05｜项目背景：为什么需要这个智能体

**建议画面**：果园总览页；可短暂展示果园面积、株数、物候期等信息。

**讲解话术**：

> 在农业院校的实训果园中，学生需要完成巡园、灌溉、施肥、病虫害观察和采收等任务。但教材、技术规程和历年记录通常比较分散；更重要的是，同一条通用种植知识并不一定适用于当前果园和当前阶段。比如，幼果膨大期是否灌溉，不仅取决于规程，还取决于果园的株数、灌溉方式和近期天气。
>
> 因此，我们将大模型定位为“受证据和工具约束的教学辅助智能体”，而不是替代农业专家。系统要求它先理解具体果园，再检索校本资料，必要时调用真实工具，最后给出有依据、有边界的建议。

### 1:05～1:50｜架构：智能体如何工作

**建议画面**：打开项目报告中的架构图，或展示一页简洁 PPT：`用户 → Agent → RAG/工具 → 来源与任务`。

**讲解话术**：

> 系统采用前后端分离架构。前端基于 Vue 3 和 TypeScript，后端基于 Spring Boot。智能体层使用 LangChain4j 编排大语言模型、会话记忆、检索增强生成，也就是 RAG，以及天气和农业计算等 Java 工具。
>
> 它的工作流程是：用户选择果园并提问后，系统先完成身份和会话校验，然后把果园名称、地区、面积、株数、灌溉方式以及人工确认的物候期注入提示词。接着，RAG 从橄榄专业资料中检索相关片段；如果问题涉及天气、降雨、温度或未来日期，智能体会调用天气工具；如果涉及株数、单位换算和稀释倍数，则调用确定性的计算工具。最后，系统通过流式方式返回答案、引用来源和工具执行过程，并保存审计日志。

### 1:50～3:35｜核心演示：智能体问答、RAG 与工具调用

**建议画面**：依次展示登录后的果园档案页和智能问答页；输入准备好的问题；停留在流式答案、来源和工具状态处。

**讲解话术**：

> 下面演示一次实际交互。当前选择的是学校东区橄榄实训果园。这里可以看到果园的基础信息和当前人工确认的物候期。这个上下文会进入本轮对话，避免智能体只基于泛化知识回答。
>
> 我们提问：“未来两天有大雨，幼果膨大期的橄榄园是否需要灌溉和施肥？同时计算 300 株、每株 20 升的灌溉量。”
>
> 可以看到，系统不是直接生成一段看似合理的文字。它首先展示工具调用状态：天气相关问题触发天气查询；数量问题触发灌溉量计算。计算结果由后端 BigDecimal 服务完成，300 株乘以每株 20 升，得到 6000 升，也就是 6 立方米。这类数值不交给模型心算，从而保证公式和单位换算可验证。
>
> 同时，智能体从知识库中检索幼果期水肥管理片段，并在回答中返回资料名称、来源、片段或页码等引用信息。最终建议会明确适用的果园与物候期，结合降雨条件给出灌溉和施肥的判断依据，并提示需要观察土壤墒情、由指导教师确认。若天气工具失败，系统会明确显示失败或缓存状态，而不会把旧数据伪装成实时数据。

### 3:35～4:25｜从对话到业务：任务与记录闭环

**建议画面**：切换“今日农事”页面，展示生成任务、任务状态；再切换“实训记录”。

**讲解话术**：

> 榄园知行的第二个关键点，是让智能体结果进入业务流程。用户可以根据果园和日期生成今日农事任务。系统会在后台组合果园档案、物候期、天气摘要和知识库资料，生成包含优先级、建议时段、依据和安全提示的结构化任务。
>
> 任务生成采用异步批次机制，前端可以查询生成状态，不会因为模型响应较慢而阻塞页面。教师可以审核或调整任务，学生领取并执行后，再提交现场现象、措施和图片等实训记录。这样，系统形成“智能建议—教师审核—学生执行—过程留痕”的教学闭环，而不是让一次对话停留在聊天窗口中。

### 4:25～5:20｜可信与工程化：为什么能用于实训场景

**建议画面**：可展示知识库管理页、用户管理页，或架构图中“日志、权限、数据库”的部分。

**讲解话术**：

> 为提升可信性与可管理性，我们做了四方面设计。第一，知识库资料需要经过上传、解析、切分、向量化和处理状态管理；文本按约 800 字分片、100 字重叠，并保留页码和物候期等元数据。第二，系统同时支持本地 H2 开发环境和 PostgreSQL 加 pgvector 部署环境，生产环境可以在数据库侧完成向量相似度检索。第三，账号采用 BCrypt 密码摘要和 JWT 鉴权，学生只能访问本人会话和记录，知识库与果园维护由管理员控制。第四，模型调用和工具调用都会记录状态与耗时，便于教师追溯建议依据。
>
> 特别是在农药、施肥、修剪和恶劣天气等高风险问题上，系统不会给出无依据的确定诊断或处方，而是强制提示核对资料、产品标签和安全间隔期，并建议由教师确认。

### 5:20～6:00｜价值、总结与展望

**建议画面**：回到系统首页或项目标题页；显示一句总结标语。

**讲解话术**：

> 总结来说，榄园知行的核心价值在于把大模型的自然语言能力，与校园果园的真实档案、校本知识、外部天气和确定性计算结合起来。它让学生能够在现场快速获得有来源的建议，让教师能够审核和沉淀教学过程，也让果园管理从分散记录走向可追溯的数字闭环。
>
> 下一步，我们将继续完善橄榄资料的标注与检索评测，引入重排序和知识审核机制，并在严格授权和教师确认的前提下探索传感器数据、图像辅助识别等能力。我们希望“榄园知行”不仅服务橄榄果园，也能成为其他农业实训场景可复用的智能体解决方案。谢谢各位评委老师。

## 四、录制中的强调点

### 必须说清的四件事

1. **为什么是智能体**：系统会结合上下文自主选择检索和工具，而不是固定问答模板。
2. **为什么可信**：回答有资料来源，事实与数字由工具验证，失败不伪造，风险操作需人工确认。
3. **为什么有业务价值**：结果能生成任务并沉淀实训记录，覆盖实际教学流程。
4. **为什么可落地**：有前后端、权限、数据库迁移、容器部署、日志和测试资产，不是只有原型页面。

### 建议避免的表述

- 不说“系统能准确诊断病虫害”或“自动给出农药处方”。
- 不说“模型永远正确”，改为“提供有来源、可复核的辅助建议”。
- 未接入真实天气 API 时，不说“实时天气”，应说“演示天气数据”或“缓存数据”。
- 不把历史测试记录说成当前代码的全量测试结果；现场如被问及，可说明正在持续完善迁移一致性与全量回归。

## 五、可选 30 秒答辩补充

**如果评委问：与普通聊天机器人有什么区别？**

> 普通聊天机器人主要依赖模型参数和当前输入。我们的系统先读取具体果园和物候期，再通过 RAG 获取校本资料；天气和数量问题会调用后端工具，结果、来源和工具状态都能回溯，并且建议可以进入任务和实训记录流程。因此它具备感知、决策、行动和反馈的智能体闭环。

**如果评委问：如何控制大模型幻觉？**

> 我们不把大模型作为唯一事实来源：专业结论优先引用知识库，实时信息交给天气工具，数值交给确定性计算服务；系统提示词要求无可靠来源时明确说明，工具失败时返回失败状态，高风险操作再由教师确认。

**如果评委问：项目接下来如何扩展？**

> 首先扩充并审核校本资料，建立标注测试集优化召回；其次接入传感器和图像辅助信息；最后在教师确认与权限审计下扩展到其他果树或农业实训场景。
