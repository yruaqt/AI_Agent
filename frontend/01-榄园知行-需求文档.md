# 榄园知行——橄榄果园智能管理与农事决策系统需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 榄园知行——橄榄果园智能管理与农事决策系统 |
| 文档类型 | 软件需求规格说明书（SRS） |
| 目标赛事 | 智能体开发大赛 |
| 项目形态 | Java 工程化智能体 + Web 管理系统 |
| 后端技术 | Java 17/21、Spring Boot 3、LangChain4j |
| 前端技术 | Vue 3、TypeScript、Vite、Element Plus |
| 模型平台 | 硅基流动或阿里云百炼 |
| 文档版本 | V1.0 |

> 本文默认研究对象为中国橄榄（青橄榄，Canarium album）实训果园。若学校实际种植的是油橄榄，需要替换物候期、栽培规程和病虫害知识库，软件架构与功能不变。

## 2. 项目背景

农业院校的橄榄实训果园同时承担教学实训、生产示范和科研观察任务。学生在开展巡园、灌溉、施肥、修剪、病虫害观察和采收等工作时，需要查询教材、实训指导书、地方技术规程以及历年管理记录。现有资料分散，查阅效率低，不同年级学生对橄榄物候期和农事规范的掌握程度也不一致。

本项目建设一个面向学校具体橄榄实训果园的智能体。系统以校本资料构建 RAG 知识库，通过 LangChain4j 编排大模型、知识检索和外部工具，结合果园档案、当前物候期与天气信息，生成有来源、可执行、可记录的农事建议。

## 3. 建设目标

1. 建设橄榄专业知识库，实现带来源引用的种植知识问答。
2. 建立学校橄榄园数字档案，记录面积、株数、树龄、品种和物候期。
3. 根据果园档案、物候期和天气生成每日农事任务。
4. 通过 Agent 自主判断是否调用天气、肥料、灌溉和药剂计算工具。
5. 保存对话、任务和实训记录，形成可回溯的教学过程。
6. 形成可独立部署、前后端完整、可以现场演示的工程化系统。

## 4. 用户角色

| 角色 | 说明 | 主要权限 |
| --- | --- | --- |
| 学生 | 参加橄榄园实训的学生 | 智能问答、查看果园、生成任务、提交实训记录、使用计算工具 |
| 教师/管理员 | 实训教师或果园管理人员 | 学生全部权限，维护果园档案、审核任务、管理知识库、查看全体记录 |

首个参赛版本可以将“教师/管理员”和“系统管理员”合并为管理员角色，仅保留 `ADMIN` 与 `STUDENT` 两种角色。

## 5. 业务范围

### 5.1 本期范围

- 单所学校、单个或少量橄榄实训果园；
- 中国橄榄种植知识问答；
- 果园档案与物候期维护；
- 基于天气和知识库的农事建议；
- 每日农事任务生成与状态管理；
- 灌溉、肥料、药剂稀释和产量估算工具；
- 知识库资料上传、解析、切分、向量化和检索；
- 对话记录、工具调用记录和实训记录；
- 阿里云百炼模型。

### 5.2 本期不做

- 不开发多智能体系统；
- 不开发无人机、自动灌溉等真实设备控制；
- 不承诺仅凭照片完成病虫害确诊；
- 不自动开具农药处方；
- 不覆盖所有果树和全部农业生产场景；
- 不开发复杂的气象预测模型；
- 不开发原生手机 App。

## 7. 核心业务流程

### 7.1 智能问答流程

1. 用户选择目标果园并输入问题。
2. 系统加载用户权限、果园档案和当前物候期。
3. Agent 分析问题，判断需要知识检索还是工具调用。
4. RAG 模块检索橄榄专业资料，返回相关片段及来源。
5. 涉及实时天气或数值计算时，Agent 自动调用对应工具。
6. 大模型融合果园上下文、检索结果和工具结果生成回答。
7. 前端展示答案、引用来源、工具调用摘要和安全提示。
8. 后端保存对话与调用记录。

### 7.2 今日农事任务流程

1. 用户点击“生成今日任务”。
2. 系统读取果园档案、当前物候期和近期未完成任务。
3. Agent 调用天气工具查询当天及未来 24 至 72 小时天气。
4. Agent 检索当前物候期的水肥、树体和病虫害管理资料。
5. Agent 生成结构化任务，包括任务名称、依据、优先级、建议时间和注意事项。
6. 用户保存任务，教师可审核，学生执行后提交结果。

### 7.3 异常辅助排查流程

1. 用户输入落果、叶片异常、枝梢异常等现象。
2. Agent 针对发生部位、范围、时间和近期天气进行追问。
3. 系统检索知识库中相关资料。
4. 输出可能原因、建议检查项目和需要记录的数据。
5. 资料不足或风险较高时，提示联系指导教师或植保人员。

## 8. 功能需求

### 8.1 用户认证与权限

#### FR-AUTH-01 用户登录

- 用户使用用户名和密码登录。
- 登录成功后返回访问令牌、用户信息和角色。
- 密码必须加密保存，不得明文入库。
- 登录失败应提示账号或密码错误，不暴露具体账号状态。

#### FR-AUTH-02 当前用户

- 用户可以查看自己的用户名、姓名和角色。
- 用户可以退出登录。
- 管理员可以新增、停用和重置用户密码。

#### FR-AUTH-03 权限控制

- 学生只能修改本人创建的实训记录。
- 果园档案、知识库和用户管理仅允许管理员操作。
- 所有管理接口必须在后端进行权限校验。

### 8.2 果园档案

#### FR-ORCHARD-01 果园查询

- 用户可以查看果园列表和详情。
- 详情包括面积、株数、树龄、品种、位置、灌溉方式和负责人。

#### FR-ORCHARD-02 果园维护

- 管理员可以新增、修改和停用果园档案。
- 面积、株数不得为负数。
- 停用果园不得再生成新任务，但历史数据必须保留。

#### FR-ORCHARD-03 物候期维护

- 管理员可以维护当前物候期、生效时间和备注。
- 系统保留物候期变更历史。
- Agent 生成建议时优先使用人工确认的当前物候期，不自行覆盖。

### 8.3 智能问答 Agent

#### FR-AGENT-01 多轮对话

- 支持针对同一会话进行连续追问。
- 对话记忆至少保留当前会话最近 10 至 20 轮消息。
- 用户可创建新会话、查看会话列表和删除本人会话。

#### FR-AGENT-02 果园上下文

- 每次提问必须携带果园 ID。
- Agent 应读取果园档案和当前物候期，并在必要时写入提示上下文。
- 回答应明确其适用的果园和物候期。

#### FR-AGENT-03 工具自主调用

- 涉及天气、降雨、温度和未来日期的问题时，Agent 应调用天气工具。
- 涉及总量、单株用量、稀释倍数时，Agent 应调用计算工具。
- 工具失败时，Agent 应说明失败原因，不得虚构工具结果。

#### FR-AGENT-04 回答结构

回答应根据问题尽量包含：

- 直接结论；
- 建议操作；
- 判断依据；
- 引用来源；
- 风险与安全提示；
- 需要进一步确认的信息。

#### FR-AGENT-05 安全边界

- 不将可能原因描述为确定诊断。
- 不推荐知识库中没有可靠依据的农药和剂量。
- 涉及农药时必须提示核对登记作物、防治对象、产品标签和安全间隔期。
- 涉及大规模施肥、用药、修剪等操作时提示由指导教师确认。

### 8.4 RAG 知识库

#### FR-RAG-01 资料上传

- 管理员可以上传 PDF、DOCX、TXT 和 Markdown 文件。
- 单个文件大小建议限制在 20 MB 以内。
- 系统记录资料名称、来源单位、发布日期、适用地区和文件类型。

#### FR-RAG-02 文档处理

- 后端完成文本解析、清洗、分段和向量化。
- 文档处理状态包括待处理、处理中、成功和失败。
- 处理失败时保留错误信息，允许重新处理。

#### FR-RAG-03 向量检索

- 根据用户问题检索相关文档片段。
- 检索结果包含文档 ID、片段内容、相似度和来源信息。
- 支持按作物、物候期、资料类型和地区等元数据过滤。

#### FR-RAG-04 来源引用

- Agent 回答需返回实际使用的知识来源。
- 引用至少展示资料名称和片段编号；具备页码时显示页码。
- 未检索到有效资料时明确标记“未找到可靠知识来源”。

### 8.5 天气工具

#### FR-TOOL-01 天气查询

- 根据果园经纬度或行政区划查询实时天气及未来天气。
- 返回温度、天气现象、降雨、风力和数据更新时间。
- 天气数据必须标明来源与更新时间。

#### FR-TOOL-02 天气失败处理

- API 超时或限流时返回明确错误状态。
- Agent 不得将历史缓存冒充实时数据。
- 可以展示最近一次成功数据，但必须标注缓存时间。

### 8.6 农业计算工具

#### FR-CALC-01 灌溉量计算

- 支持按株数与单株用水量计算全园用水量。
- 输出升和立方米两种单位。

#### FR-CALC-02 肥料量计算

- 支持按株数和单株用量计算总量。
- 支持克、千克、吨的单位换算。

#### FR-CALC-03 药剂稀释计算

- 根据目标药液体积和稀释倍数计算原药理论用量。
- 明确显示公式、输入值、结果和安全提示。

#### FR-CALC-04 产量估算

- 根据抽样株数、平均单株产量和果园总株数估算总产量。
- 结果必须标记为估算值，不作为最终产量数据。

### 8.7 农事任务

#### FR-TASK-01 任务生成

- 用户可以按果园和日期生成农事任务。
- Agent 输出结构化任务，不只输出聊天文本。
- 每项任务包含类型、内容、优先级、建议执行时间、依据和安全提示。

#### FR-TASK-02 任务管理

- 任务状态包括待确认、待执行、执行中、已完成和已取消。
- 教师可以修改、确认或取消 Agent 生成的任务。
- 学生可以领取任务并提交执行结果。

### 8.8 实训记录

#### FR-RECORD-01 记录提交

- 学生可以填写日期、果园、任务、抽查株数、异常株数、现象和处理措施。
- 支持上传少量现场图片作为记录材料。
- 记录必须关联提交人和提交时间。

#### FR-RECORD-02 记录查询

- 支持按果园、日期、任务类型和提交人筛选。
- 教师可以查看全部记录并填写评语。

### 8.9 模型配置

#### FR-MODEL-01 平台切换

- 后端支持硅基流动和阿里云百炼兼容 API。
- 模型平台、基础地址、模型名称、超时和温度参数通过配置文件或环境变量设置。
- API Key 只能保存在后端环境变量，不得返回给前端或写入 Git。

#### FR-MODEL-02 调用日志

- 保存模型平台、模型名称、耗时、是否成功和错误摘要。
- 可选记录 Token 使用量，不记录密钥。

## 9. 非功能需求

### 9.1 性能

- 普通 CRUD 接口在本地环境下平均响应时间不超过 1 秒。
- 不含模型生成时间的 RAG 检索目标响应时间不超过 2 秒。
- Agent 首次响应目标时间不超过 8 秒，完整回答目标时间不超过 30 秒。
- 前端采用流式输出，避免用户长时间看到空白页面。

### 9.2 稳定性

- 模型、Embedding 或天气服务失败时，后端返回可识别的错误码。
- 外部 API 设置连接和读取超时。
- 同一工具调用失败后最多有限次数重试，避免无限循环。

### 9.3 安全性

- 密码使用 BCrypt 等安全算法保存。
- 使用 JWT 或等效机制完成身份认证。
- 上传文件进行扩展名、MIME 类型和大小校验。
- 防止越权访问他人会话和实训记录。
- 日志中对令牌、API Key 和密码进行脱敏。

### 9.4 可维护性

- 后端按认证、果园、知识库、Agent、工具、任务和记录划分模块。
- 对外接口生成 OpenAPI/Swagger 文档。
- 关键业务和工具计算具有单元测试。
- 模型平台通过统一接口封装，避免业务代码绑定单一供应商。

### 9.5 可部署性

- 提供 Docker Compose 部署方式。
- 提供数据库初始化脚本、环境变量示例和模型权重/API获取说明。
- 支持在比赛提供的服务器或昇腾 NPU 环境周边服务中部署；若模型通过 API 调用，应在部署文档中说明网络和密钥配置。

## 12. 验收标准

1. 用户可以登录并按角色访问对应页面。
2. 管理员可以维护至少一个橄榄园档案及当前物候期。
3. 系统可以导入不少于 20 份橄榄相关资料并完成向量化。
4. 预设测试问题中，回答能够展示实际检索到的来源。
5. Agent 可以自主完成至少一次天气 API 调用。
6. Agent 可以自主调用至少两种 Java 计算工具，并返回正确结果。
7. 系统可以生成结构化农事任务并保存、更新状态。
8. 学生可以提交实训记录，教师可以查看并评价。
9. 模型或天气 API 失败时，系统能够给出明确提示而不是伪造结果。
10. 项目可以按照部署文档在新环境中启动，并完成前后端联调。

## 13. 比赛演示用例

1. 登录学生账号，查看学校东区橄榄实训果园档案。
2. 点击生成今日任务，展示 Agent 调用天气和 RAG 后输出的任务。
3. 提问“未来两天有大雨，幼果期橄榄园是否需要灌溉和施肥”。
4. 提问“300 株橄榄树，每株施肥 12 千克，总量是多少”，展示工具调用。
5. 提问“近期幼果落果较多，应先检查什么”，展示追问、知识引用和安全边界。
6. 保存一项任务并提交实训记录。

## 14. 主要风险及对策

| 风险 | 对策 |
| --- | --- |
| 橄榄资料数量不足 | 优先收集学校教材、地方标准和农技推广资料，并记录来源 |
| 大模型产生错误建议 | 强制 RAG 引用、低置信度拒答、工具结果校验、教师确认 |
| API 网络不稳定 | 设置超时和错误提示，准备录屏及非实时演示数据作为比赛备用材料 |
| 新成员开发能力有限 | 将认证、CRUD、计算器拆为明确模块，由负责人提供模板并代码审查 |
| 前后端联调延期 | 第一周确定接口契约，使用 Swagger 和 Mock 数据并行开发 |
| 项目范围失控 | 首版不加入图像识别、物联网和多智能体，只完成核心闭环 |
